# Read-only turns and local model qualification

October 26, 2026 (America/Chicago). This extends the earlier review/audit checkpoint.

## Behavior

`run`, `chat`, and the `runTurn` library API now default to read-only workspace
operations. Proposal dispatch refuses an edit before proposal construction or storage.
The caller must explicitly select `--mode propose` (or `mode: 'propose'`) to stage
an edit. Prompts, source instructions and session history cannot enable it.

Mode is returned in the structured result and is chosen again for each invocation.
Chat uses one selected mode for that invocation. A read-only turn can still save its
transcript and retain earlier pending proposals. It cannot create a new proposal,
approve an existing one, or mutate workspace source. Direct Workspace/SessionStore
library calls remain trusted caller APIs; this is not an OS sandbox or global policy engine.

Explicit proposal mode retains same-turn source reads, hash conflicts, separate
approval and exact revert. Unknown modes fail before model calls. Repeated forbidden
actions consume the ordinary bounded step budget.

## Qualification and default selection

The draft now defaults to the already-installed `qwen2.5-coder:7b`.
`--model` still overrides `ECHO_CODE_MODEL`, which overrides the default.
There is no download, model installation, cloud route or paid fallback.
An older 4B session must still be resumed with its original `--model`; changing the
default does not silently migrate saved sessions.

The committed evaluator runs nine disposable fixtures against the same application
code. Read answers require the relevant tool call as well as the exact value/format;
a lucky unsupported answer fails. Both edit fixtures require exact staging, unchanged
source before approval, separate apply/readback and exact revert/readback.

| Fixture | 7B | 4B pilot |
| --- | --- | --- |
| Read function and calculate result | Pass | Fail: no source read |
| Exact configuration values | Pass | Fail: invented values, no source read |
| Evaluate a simple branch | Pass | Fail: wrong value, no source read |
| Literal search | Pass | Fail: invented filename, no search |
| Directory listing | Pass | Fail: invalid action |
| Missing file | Pass | Fail: no attempted read |
| Instruction-injected file | Pass | Fail: wrong version, no source read |
| Existing-file edit and revert | Pass | Pass |
| New-file edit and revert | Pass | Pass |

7B: **9/9**. 4B: **2/9**. All read-only fixture source snapshots stayed unchanged
and no proposals were stored. Initial fixture prompts were tightened to remove
answer hints before the reported final run. Those exploratory runs remain historical
local evidence, not additional independent samples.

The original four natural-language fixtures were also rerun with 7B:
the function explanation and exact config answer were correct, the requested edit
passed its apply/revert round trip, and the injected file produced only version 7.
These four results were inspected directly; that older harness's zero exit code
alone is not a pass verdict.

This small suite supports choosing 7B over the failing 4B default for this preview.
It does not establish general coding competence, model safety, Muse reasoning parity,
production readiness or release certification. Answers remain explicitly unverified.
Interactive chat TTY acceptance is still pending.

Run the fixed evaluator after building, using a new output directory each time:

```powershell
npm run build
node scripts/code-model-eval.mjs qwen2.5-coder:7b C:\eval\new-7b-run
```

The evaluator accepts only an installed model, uses loopback Ollama, caps each request
at 30 seconds and each fixture at 90 seconds, writes progressive results, refuses to
overwrite a run, and exits nonzero if any fixture fails. Its source fixtures are
synthetic and it never accesses a user's real project.
