# Authentic CI and CodeQL checks

Release Sentinel reported that the required `CI` and `CodeQL` checks were absent
at candidate `5cdb48d`. The existing workflow ran lint, TypeScript, tests and build
under the default job check name `test`. It now explicitly names that same real
job `CI` and installs the committed dependency lock with `npm ci`.

A separate `CodeQL` job analyzes JavaScript and TypeScript without a build step.
Its checkout and CodeQL actions are pinned to commit identities retrieved from the
official GitHub repositories. CodeQL v4.39.1 resolves to
`9b3254085494b55a0f7c4c2b3d2d52cc712ce370`; checkout v4 resolves to
`11d5960a326750d5838078e36cf38b85af677262`. The analysis job has repository-content
read and security-event upload permissions; checkout does not persist credentials.

The current repository was verified public. GitHub documents advanced CodeQL
setup for public repositories at
https://docs.github.com/en/code-security/how-tos/find-and-fix-code-vulnerabilities/configure-code-scanning/configuring-advanced-setup-for-code-scanning
and the action implementation at https://github.com/github/codeql-action.
No repository visibility, organization entitlement, account credential, branch
protection or SDK permission is changed by this workflow patch.

Hosted results must be read back for the resulting exact source SHA. Passing CI
and CodeQL are separate from owner admission, trusted production E2E attestation,
independent review and deployment. The earlier signed staging verdict for
`5cdb48d` does not certify a later workflow commit.
