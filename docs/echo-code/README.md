# ECHO Code 0.1.0 — local preview

A small ECHO-native coding assistant built inside the existing ECHO CLI. It runs against an installed local Ollama model and can inspect source, stage an edit, preserve a session and expose read-only source tools over local MCP. It does not need a Meta subscription or API key. Your machine still supplies the computing resources.

Build from the repository with Node >=20:

```powershell
npm ci --ignore-scripts
npm run build
node dist/code-main.js doctor
node dist/code-main.js run "Read src/example.ts and explain it" --workspace C:\path\to\source
```

The separate `echo-code` binary is added to the package. It does not initialize or alter the older CLI's stored API-key configuration. Default endpoint is http://127.0.0.1:11434 and model is qwen2.5-coder:7b; use --model for another already-installed local model. A missing model fails; there is no download or paid fallback. For another operator-owned machine, establish an authorized loopback tunnel separately; the application itself accepts only loopback origins.

`run` and `chat` default to `--mode read-only`. The dispatcher refuses proposals
before constructing or storing an edit, even when a prompt, source file, prior turn,
or model response requests one. Select `--mode propose` explicitly to stage edits.
Mode applies to the current run or chat invocation and is not inherited on resume.
The JSON result reports the effective mode. Existing pending proposals are retained;
read-only mode neither approves nor discards them. Session transcripts still persist
locally, so read-only describes workspace operations, not a filesystem sandbox.

Review and apply:

```powershell
node dist/code-main.js run "Read example.ts and stage the requested change" --mode propose --workspace C:\source
node dist/code-main.js show SESSION_ID
node dist/code-main.js approve SESSION_ID PROPOSAL_ID --workspace C:\source
node dist/code-main.js revert SESSION_ID PROPOSAL_ID --workspace C:\source
```

Replace the displayed IDs, and inspect both original and proposed text before approval. Source changes only in the separate approve invocation. Revert refuses to overwrite later edits. Session files include local source excerpts/backups; use a private --state-dir and do not share them as telemetry.

Other commands: chat (terminal required), sessions, run --session ID (same model/workspace), recover ID (after interruption), mcp --workspace PATH (stdio server), integrations (shared-owner contract/readiness view). Use --help for exact options. Interactive chat has not received manual TTY acceptance; the tested paths are headless and fresh-process CLI/MCP operations.

Omnipresence should be the shared runtime owner and Sentinel the independent observer. A tested host-broker adapter is included; standalone operation does not attach that broker or activate the Single Runtime Engine. See OWNER_INTEGRATION.md for measured scopes, current limits and the activation contract still required.

MCP launch configuration for a local host:

```json
{
  "command": "node",
  "args": ["C:/absolute/path/to/dist/code-main.js", "mcp", "--workspace", "C:/source-only-workspace"]
}
```

This preview is an independent implementation informed by public Muse contracts. It has no Muse engine dependency, does not implement MSP, and does not reproduce Muse Spark model quality. The installed small model produced unreliable explanations during acceptance. Treat every model answer and proposed change as requiring review. All model-generated final answers carry an explicit unverified flag; the approval message is generated by the application.

ECHO repository work still requires its current doorway chain, admission and preflight. This CLI is not a policy enforcement or certification service. No shell, deployment, automatic project hooks, fleet authority or OS sandbox is included. See the behavioral spec, parity matrix, threat model and acceptance report for precise evidence and limits.

## Review and audit continuation (October 26, 2026)

The local continuation adds:

- `review SESSION_ID PROPOSAL_ID --workspace PATH`: complete before/after text,
  integrity-checked unified diff, and newline metadata. Terminal controls are
  escaped in the display; approval still uses the original hash-bound proposal.
- `reject SESSION_ID PROPOSAL_ID --workspace PATH`: durable, repeatable rejection
  without a source write. Rejected proposals cannot later be approved.
- Fresh per-turn source reads before replacing an existing file. Changed or
  unread source prevents staging; returned source hashes are evidence of reads,
  not proof that generated prose is correct.
- Metadata-only local audit records for CLI `review`, `approve`, `reject`,
  `revert`, and `recover` after their workspace/state context is constructed.
  `events.jsonl` lives in the selected private state directory and contains only
  fixed event/operation/status names, UTC time, opaque session/correlation IDs,
  and elapsed time. It has a 5 MiB ceiling and refuses linked files/directories.
  A busy, full, or unsafe sink emits a fixed stderr warning and does not change
  an operation's actual result. This is a best-effort local trace, not a durable
  compliance ledger or verified ECF capture. Direct library calls, run/chat,
  MCP requests, argument parsing, and context-construction failures are not
  covered by this command-level audit.

The original fresh-process CLI and stdio MCP regression checks remain in
`tests/code-process.test.ts` alongside the in-process review tests.

The installed `qwen2.5-coder:7b` was evaluated on four disposable fixtures.
It correctly staged/applied/reverted the requested arithmetic edit and answered
the injected-instruction fixture, but staged proposals for two read-only
questions instead of answering. No source changed without separate approval.
That result is historical. The subsequent read-only increment and fixed evaluation qualified 7B as the preview default; see [Read-only turns and model qualification](READ_ONLY_2026-10-26.md) for the bounded 9/9 versus 2/9 comparison and remaining limits.


## Explicit durable memory checkpoints

The memory prepare/status/sync commands preserve an explicit summary and its stable
request ID across restarts. An attached existing host broker can capture and verify
that summary through Fabric. The current SDK connection lacks continuity.write,
so no live save is claimed. Standalone sync reports its missing broker and exits 2.
See [checkpoint behavior and evidence](CONTINUITY_2026-10-26.md) and the
[shared runtime admission proposal](RUNTIME_ADMISSION_PROPOSAL.md).

## Shared owner host integration

The programmatic runSharedTurn entrypoint binds this client to an explicitly admitted owner coding contract through an authenticated host broker. See [the host integration contract](SHARED_RUNTIME_2026-10-27.md). The standalone CLI does not attach credentials or activate this path automatically.
